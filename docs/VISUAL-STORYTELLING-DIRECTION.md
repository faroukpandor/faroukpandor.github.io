# Visual Storytelling Direction

## Why

Napkin AI turns existing text into diagrams, charts, flowcharts, mind maps and other visuals, with editable styles and export options. citeturn0search1turn0search3

The portfolio can adopt that **communication principle** without copying Napkin's product, interface or branding.

## Principles

- Text/data remains canonical; visuals explain.
- One idea per visual.
- Flow and relationships before decoration.
- Static-first HTML/CSS/SVG; no AI dependency for core pages.
- AI, if added later, is a drafting layer subject to human review.
- Evidence labels remain visible.
- Portfolio routing should be visually understandable.
- Use an original Farouk visual language.

## Current implementation

The homepage now includes an original visual operating model:

**Need → Diagnose → Assemble → Deliver → Outcome**

and five capability routes:

**Research / Commercial / Digital / Agriculture / Network**

It uses ordinary HTML/CSS and adds no runtime API, database or paid SaaS dependency.

## Future AI enhancement

Potential architecture:

**Canonical text/data → visual specification → generated candidate → human review → accessibility check → static SVG/HTML asset → publication**

Generated visuals must never silently convert a hypothesis into a fact.

## Commercial opportunity

After the approach is demonstrated internally, it can become part of a potential visual decision-support / visual business communication service:

**research / strategy / business requirement → visual decision artefact → customer-ready report, diagram or presentation**

No market demand is assumed until customer validation.
