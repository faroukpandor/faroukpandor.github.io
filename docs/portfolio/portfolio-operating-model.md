# Portfolio Operating Model

## Objective
Operate Farouk Pandor's digital estate as a governed portfolio rather than a collection of disconnected projects.

## Asset layers
1. Identity and public portfolio
2. Enterprise/product repositories
3. Client/partner repositories
4. Google AI Studio prototypes
5. Documentation/research
6. Deployments/domains
7. Reusable IP/components
8. Archives and historical evidence

## Decision sequence
Problem → Customer → Evidence → Solution → Value → Competition → Business Model → Risk/Compliance → Digital Asset → Revenue → Scalability.

## Ownership rule
Ownership, authorship, repository control, client rights and licensing are separate questions. Record each separately when evidence exists.

## One-canonical-product principle
A product may have many experiments, but should have one clearly identified canonical production source whenever practical.

## Collective rule
Maximise useful reuse while avoiding destructive consolidation. Preserve evidence first; consolidate second.
