# Portfolio-wide UI Design Standard

All Farouk Pandor-owned web applications should progressively adopt a common **Visual Thinking × Visual Storytelling** interaction philosophy inspired by current patterns from Napkin AI and Gamma.

This is not a cloning programme.

## Reference synthesis

Napkin demonstrates a text-first path from content to meaningful visuals and distinguishes visual building blocks from complete presentations. Gamma demonstrates goal-first generation, structured narratives, flexible layouts, conversational refinement and multiple output formats. citeturn0search0turn0search7turn0search4turn0search6

Our portfolio synthesis is:

**Goal → Source/Idea → Structure → Evidence → Visualise → Decide → Act → Share**

## Portfolio rule

One philosophy, many identities.

AgriSage360 should feel agricultural.
Africa Realty/PANDOR-ESTATES should feel property-focused.
EverythingCity should feel commerce/procurement-focused.
MOKORO should feel digital-growth/automation-focused.
Personal command centres should feel focused and operational.
One Health applications should feel evidence-led and safety-conscious.

They should not become identical clones.

## Mandatory UI characteristics

- purpose visible immediately;
- one clear primary action;
- progressive disclosure;
- information presented as meaningful blocks;
- visual relationships exposed when they improve comprehension;
- source/evidence/status visible;
- uncertainty distinguishable from fact;
- draft/refine/share or equivalent lifecycle;
- mobile-first;
- accessible;
- performance-conscious;
- offline-first where the application's architecture calls for it;
- lightweight visual primitives before heavy canvas/runtime dependencies;
- no decorative AI visual noise;
- no fabricated metrics, evidence or authority.

## Reusable product concepts

Where appropriate, applications should converge on equivalents of:

**StoryCard · VisualNode · EvidenceChip · DecisionCard · SourceBadge · WorkflowStep · OutputMode · InsightPanel · Workspace/Canvas · Dossier/Presentation renderer**

These are conceptual primitives, not mandatory component names.

## Ownership/provenance rule

Only repositories with established authority should receive implementation changes.

Client-owned, collaborator-only, forked or third-party repositories require provenance/licence/authorization review first. A shared UI philosophy does not establish IP ownership.

## Quality gate

A webapp is considered aligned only after:
- the main user journey is obvious;
- visualisation adds meaning;
- narrative structure is coherent;
- evidence is distinguishable from inference;
- mobile/touch/keyboard behaviour works;
- core flows remain performant;
- build/type checks pass;
- the product still has its own identity.
